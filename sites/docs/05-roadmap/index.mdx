[RFC méthode de travail](/00-produit/methode-de-travail)). La liste d'issues en fin de page est
prête à être créée dans le GitHub Project.

## L'objectif

**Permettre à une association de suivre le cycle de vie d'un amendement** : de son dépôt à son
sort final, en passant par chaque étape d'examen, sans rien manquer et en sachant toujours ce qui
est officiel et ce qui est déduit.

Le parcours de base existe déjà (mode DEV_FRONT) : **sélectionner des textes → les suivre →
ouvrir un article → voir ses amendements par étape (kanban)**.

## Le cycle de vie d'un amendement

<Mermaid
  chart={`flowchart LR
  D["Dépôt<br/>délai : 3e jour ouvrable, 17 h"] --> R{"Recevable ?"}
  R -- non --> I["Irrecevable<br/>art. 40 / art. 45"]
  R -- oui --> C["Commission<br/>pour avis / au fond"]
  C --> S1{"Sort"}
  S1 -- adopté --> T["Intégré au texte<br/>de la commission"]
  S1 -- rejeté / retiré / tombé --> RS["Redépôt en séance ?<br/>nouveau numéro, lien probable"]
  RS --> SP["Séance publique"]
  T --> SP
  SP --> S2{"Sort final"}
  S2 --> N["Navette<br/>Sénat (après V0)"]`}
/>

| Étape | Ce que l'utilisateur doit voir | Où | État |
| --- | --- | --- | --- |
| Dépôt | nouveaux amendements sur ses textes, délai de dépôt | Accueil, kanban « Déposés » | ✅ affichage · ⏳ délai (DW-30) |
| Recevabilité | irrecevable et motif (art. 40, art. 45) | statut, fiche amendement | ✅ statut · ⏳ motif (DW-22) |
| Commission | colonne « au fond » / « pour avis », échéance J-n | kanban | ✅ |
| Sort | adopté, rejeté, tombé, retiré, non soutenu | badges, filtres | ✅ |
| Sous-amendements | arbre parent → sous-amendements | fiche amendement | ✅ mention · ⏳ arbre (DW-24) |
| Similaires | groupes ≥ 85 % | kanban (bordure sarcelle) | ✅ maquette · ⏳ calcul réel (DW-25) |
| Redépôt en séance | « redéposé en … ? à vérifier » | kanban, fiche | ✅ maquette · ⏳ calcul réel (DW-26) |
| Séance | colonne séance, sort final | kanban, frise | ⏳ données (DW-15) |
| Sénat | navette | hors V0 | ⏳ (DW-42) |

## Ce qui est fait

- **Monorepo** : `packages/` (theme, brand, data, api, state, ui, screens), `sites/` (web, docs), `server/`.
- **Design system** : tokens du styleguide, thème Mantine, écarts maquettes ↔ styleguide tranchés, une page de doc par composant.
- **Marque** : pictogramme vectoriel, logos, favicons, image OG, 16 propositions de logo.
- **Écrans** : connexion (session de démonstration), accueil, recherche, ajouter des textes, mes textes, fiche texte, article (liste / avancement / groupe), amendements suivis.
- **Données** : hooks TanStack Query, mode DEV_FRONT (mock) et mode API ; textes suivis et session dans le navigateur (Zustand).
- **API** : FastAPI selon la RFC — recherche Meilisearch, dossiers, articles, amendements, santé.
- **Qualité** : Biome, lefthook, commitlint, ruff, CI ; tests Vitest, Playwright + axe, pytest.
