L'application et la documentation se déploient ensemble, depuis le dépôt GitHub, avec **une seule
ressource Coolify** de type Docker Compose. Tout est décrit dans trois fichiers :

| Fichier | Rôle |
| --- | --- |
| `docker-compose.yml` | les deux services (`web`, `docs`) et leurs domaines |
| `sites/web/Dockerfile` | image Next.js « standalone » (Node 22, ~40 Mo d'application), port 3000 |
| `sites/docs/Dockerfile` + `sites/docs/nginx.conf` | doc statique servie par nginx, port 80 |

## Mise en place (une fois)

1. **Créer la ressource** : *Project* → *New resource* → *Public/Private repository* (ou *GitHub App*)
   → choisir le dépôt et la branche `main`.
2. **Build pack** : *Docker Compose*.
   - *Base Directory* : `/`
   - *Docker Compose Location* : `/docker-compose.yml`
3. **Domaines** : Coolify en génère un par service grâce aux variables `SERVICE_FQDN_WEB_3000` et
   `SERVICE_FQDN_DOCS_80`. Pour utiliser les vôtres, onglet *Domains* de chaque service, en gardant
   le port interne :
   - `web` → `https://app.democracy-watch.fr:3000`
   - `docs` → `https://docs.democracy-watch.fr:80` (port 80 : peut être omis)
4. **Déployer**. Les deux images se construisent depuis la racine du dépôt (contexte = monorepo).
5. **Déploiement automatique** : activer le webhook GitHub (*Webhooks* / *Auto deploy*) pour
   redéployer à chaque push sur `main`.

Le nom de domaine public de l'application est transmis au build (`SITE_URL`) : il sert aux balises
de partage (image OG absolue). **Redéployer après un changement de domaine.**

Tant que l'API n'est pas déployée, l'application est construite en mode **DEV_FRONT** (données
fictives, `sites/web/.env.production`). Pour brancher l'API, définir au build
`NEXT_PUBLIC_API_MODE=API` et `NEXT_PUBLIC_API_URL` (voir [API](/serveur/api)).

## Vérifier

- Chaque image a un *healthcheck* : `web` interroge `/connexion`, `docs` interroge `/`.
- En cas de « No Available Server » : vérifier que le port interne figure dans le domaine
  (`:3000` pour `web`) et lire les *Deployment Logs* puis les *Runtime Logs*.

## Tester les images en local

Docker doit être lancé :

```bash
docker compose -f docker-compose.yml -f docker-compose.local.yml up --build
# web  → http://localhost:3000
# docs → http://localhost:3002
```

`docker-compose.local.yml` ne fait qu'ouvrir les ports ; il n'est pas utilisé par Coolify (le
proxy de Coolify route le trafic, publier des ports le contournerait).

## Plus tard

- **Variables d'environnement** (accès à l'API ou à la base) : les déclarer dans
  `docker-compose.yml` sous `environment` (`- API_URL=${API_URL:?}` bloque le déploiement tant
  qu'elle n'est pas renseignée) puis les remplir dans l'onglet *Environment Variables*.
- **API Python** (`server/`) : ajouter un troisième service au même fichier, avec son propre
  `SERVICE_FQDN_API_8000`.
- **Prévisualisation des pull requests** : *Preview Deployments* de Coolify, sur la même ressource.
